Data Structures and Algorithms

Understand the concept. Write the code. Solve the problem.

1. 🧱 Data Structures

A data structure is a way of organizing and storing data so we can use it efficiently.

🔗 Linear

Elements are arranged in a sequence.

  • Array
  • Linked List
  • Stack
  • Queue

🌳 Non-Linear

Elements can have hierarchical or network relationships.

  • Tree
  • Graph
  • Trie
  • Heap

Static vs Dynamic

📌 Static-size data structures

A fixed-size structure has a capacity decided in advance. A traditional C array is an example. 

int numbers[5];

Here, the array has space for 5 integers.

📌 Dynamic data structures

Their size can change while a program runs. A linked list is one example. 

numbers = [10, 20, 30]
numbers.append(40)
print(numbers)
Output: [10, 20, 30, 40]

Python lists can grow dynamically. The same static/dynamic distinction depends on implementation for stacks and queues.

2. ⚙️ Algorithm

An algorithm is a finite sequence of well-defined steps used to solve a problem.

Example: Add two numbers

  1. Start
  2. Take two numbers, A and B
  3. Calculate A + B
  4. Display the result
  5. Stop
💡 Why do we study algorithm efficiency?

The same program may run at different speeds on different computers. Instead of relying only on clock time, we analyse how the work grows as the input size increases.

Counting source-code lines is also not enough: one line may contain a loop that performs thousands of operations.

3. ⏱️ Time Complexity

Time complexity describes how an algorithm's work grows as the input size n increases.

O(1)

Constant

print("Hi")

Fixed amount of work, independent of n.

O(n)

Linear

for x in numbers:
    print(x)

Work grows with the number of elements.

O(log n)

Logarithmic

Example: binary search on sorted data.

Each step reduces the search space significantly.

O(n log n)

Linearithmic

Example: merge sort.

Common in efficient sorting algorithms.

O(n²)

Quadratic

for x in numbers:
    for y in numbers:
        print(x, y)

Two nested loops each iterate over n elements.

⭐ Important: Why is it not O(2)?

A program that performs a fixed number of operations, such as two print statements, is still O(1).

Big O ignores constant factors. O(2), O(10) and O(100) all belong to O(1), when those numbers are fixed.
